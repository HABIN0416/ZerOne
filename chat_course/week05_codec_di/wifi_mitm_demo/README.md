# 시연: "우리도 모르게 누가 중간에서 다 본다" (Windows 모바일 핫스팟 · 악성 무료 와이파이)

**목적**: 통신의 위험성 알리기 — 마음먹은 누군가는 우리가 모르는 사이 중간에 끼어
평문을 다 읽을 수 있음을 눈으로 보여 주고, 그래서 서버가 갖춰야 할 보안 개념으로 잇는다.

**핵심 그림** (기계 2대 — 순수 파이썬, tshark·관리자 권한·패킷 파싱 불필요):
```
학생들(Windows) ──▶ [Free_WiFi 핫스팟] sniffer.py :5000 ──▶ 다른 컴퓨터 server.py :5000
  평소처럼 접속·채팅할 뿐                 (몰래 엿보는 중간자)      (진짜 서버, 같은 핫스팟에 붙음)
```
- **핫스팟 노트북**: `sniffer.py` 실행 (학생을 받아 진짜 서버로 중계하며 몰래 엿봄)
- **다른 컴퓨터**(같은 Free_WiFi에 접속): `server.py` 실행 (진짜 채팅 서버, 0.0.0.0:5000)
- 학생은 **아무 설정도 안 바꿉니다.** 무료 와이파이에 붙어 채팅할 뿐인데 sniffer 가 다 훔쳐봅니다.
- 모두 포트 5000 (핫스팟 노트북과 서버가 다른 기계라 겹치지 않음).

> "서버는 저 멀리 다른 컴퓨터에 있는데도 중간(핫스팟)에서 다 털린다" — 이게 이 구성의 강조점.
> (기계 하나로 하고 싶으면 server.py 를 sniffer 노트북에서 돌리고 sniffer 의 SERVER_HOST 를
>  127.0.0.1 로 두면 됩니다. 단 그땐 server.py 의 PORT 를 5001 로 바꿔 충돌을 피하세요.)

> ⚠️ **반드시 내가 만든 이 핫스팟 + 실습 참가 학생에게만.** 학교 공용 와이파이나 남의
> 트래픽을 건드리면 안 됩니다(불법·정책 위반). 이건 '내 실습망'에서의 교육용 시연입니다.

## 1) 시연자 노트북: Free_WiFi 핫스팟 켜기 (Windows 10/11)
1. `설정 → 네트워크 및 인터넷 → 모바일 핫스팟` 켜기
   - "다음에서 인터넷 연결 공유": 붙어 있는 Wi-Fi 선택 (인터넷이 안 터져도 시연엔 무방)
   - 네트워크 이름을 `Free_WiFi` 처럼 그럴듯하게 바꿔도 좋음 (연출)
   - 핫스팟이 안 켜지면: 노트북을 아무 Wi-Fi에 먼저 접속시킨 뒤 다시 시도
2. 핫스팟 IP 확인: `명령 프롬프트`에서
   ```
   ipconfig
   ```
   → "로컬 영역 연결* (모바일 핫스팟)" 의 IPv4 주소. 보통 **192.168.137.1** 입니다.
   이 주소를 학생에게 알려 줍니다.

## 2) 다른 컴퓨터: 진짜 서버 실행 (먼저)
1. 이 폴더를 **그 컴퓨터에도** 복사하고, 그 컴퓨터를 **같은 Free_WiFi 핫스팟에 접속**시킵니다.
2. 서버 실행:
   ```
   python server.py        # 0.0.0.0:5000 (HOST 는 이미 0.0.0.0 세팅됨)
   ```
3. 그 컴퓨터의 IP 확인: `ipconfig`(Windows) / `hostname -I`(우분투) → 예 `192.168.137.50`
4. 방화벽에서 **5000 인바운드 허용**:
   - Windows: 첫 실행 때 팝업 → **개인/공용 모두 허용**
   - 우분투: `sudo ufw allow 5000/tcp`

## 3) 핫스팟 노트북: 중간자 실행
1. `sniffer.py` 를 열어 **SERVER_HOST 를 위 서버 IP로** 바꿉니다:
   ```python
   SERVER_HOST, SERVER_PORT = "192.168.137.50", 5000   # ← 다른 컴퓨터 IP
   ```
2. 실행:
   ```
   python sniffer.py       # 0.0.0.0:5000 에서 학생을 받아 서버로 중계
   ```
   - Windows 방화벽 팝업 뜨면 **개인/공용 모두 허용** (학생이 핫스팟으로 접속하려면 필요).

## 4) 학생들(각자 Windows): Free_WiFi 접속 후 채팅
- 이미 가진 **`week05_codec_di/client.py`** 를 그대로 씁니다(새 파일 배포 불필요).
- 딱 한 줄만: `HOST = "192.168.137.1"` (**핫스팟 노트북** IP — 서버 IP 아님!), `USE_SECRET = False`
  - ⚠️ 서버(다른 컴퓨터) IP로 직접 접속하면 sniffer 를 건너뛰어 아무것도 안 잡힙니다.
- 실행: `python client.py` → 닉네임 입력 후 대화
  - ※ `client.py` 옆에 `messages.py`·`codec.py` 가 함께 있어야 함(원래 week05 폴더면 OK)

## 5) 시연: 다 보인다 😱
학생들이 채팅하면 **핫스팟 노트북의 sniffer 창**에 실시간으로 뜹니다:
```
  😱 [탈취 성공] 학생 → 서비스  |  TEXT|철수|id=chulsu pw=1234
```
- 학생에게 일부러 **아이디/비밀번호 같은 걸** 쳐 보라고 하면 충격이 큽니다.
- 한글도 그대로 보입니다(파이썬이라 tcpdump 와 달리 안 깨짐).

## 6) 반전: 암호화하면 못 본다 🔒
1. **서버(다른 컴퓨터)**: `server.py` 의 `USE_SECRET = True` 로 바꾸고 다시 실행
2. **학생 전원**: `client.py` 의 `USE_SECRET = True` 로 바꾸고 재접속
3. 같은 채팅을 sniffer 로 보면:
```
  🔒 [탈취 실패] 학생 → 서비스  |  fm9yflbGmIrGorJWQ04X...   ← 알아볼 수 없음
```
> 강조: 중간자(sniffer) 코드는 **한 줄도 안 바꿨습니다.** 양끝이 Codec 부품만
> 암호화로 갈아끼웠을 뿐 — 이번 주 배운 '부품 교체'의 실전 증거.

### (심화) "이 암호도 사실 약하다"
`sniffer.py` 의 `SHOW_CRACK = True` 로 켜면, 코드에 박힌 열쇠(42)로 되돌려 봅니다:
```
  🔒 [탈취 실패] ...
      └ (박힌 열쇠 42 로 복호화) TEXT|철수|비밀번호...   ← 그래서 진짜 보안이 아니다!
```
→ 열쇠가 코드에 있으면 XOR 은 쉽게 뚫린다. **진짜 보안은 TLS.**

## 7) 결론 — 서버 개발이 갖춰야 할 보안 개념 (이 시연이 향하는 곳)
1. **전송 구간 암호화 (TLS)** — 네트워크는 신뢰 못 한다. 길목의 누구도 못 읽게.
   (우리 `USE_SECRET` 이 그 축소판)
2. **서버 인증 (인증서)** — "내가 접속한 게 진짜 서버가 맞나?" 오늘처럼 중간자가
   가짜로 낄 수 있으니, 클라이언트가 서버 신원을 확인해야 한다. (evil twin 을 막는 핵심)
3. **무결성** — 중간자는 훔쳐보기만이 아니라 **위·변조**도 가능 → 메시지 무결성 검증.

## 8) 뒷정리
- 시연 후 `server.py`/`sniffer.py` 종료(Ctrl+C), 모바일 핫스팟 끄기.
- `USE_SECRET` 은 다시 `False` 로, `sniffer.py` 의 `SERVER_HOST` 도 원복해 두면 됩니다.

## 파일 (이 폴더를 두 컴퓨터에 모두 복사)
| 파일 | 실행 위치 | 역할 |
|------|----------|------|
| `server.py` | **다른 컴퓨터** | 진짜 채팅 서버 (0.0.0.0:5000) |
| `sniffer.py` | **핫스팟 노트북** | 몰래 엿보는 중간자 (0.0.0.0:5000 → 서버 IP:5000). `SERVER_HOST` 수정 |
| `messages.py`/`codec.py`/`interfaces.py` | 다른 컴퓨터 | server 가 쓰는 부품 |
| (학생) `week05_codec_di/client.py` | 학생 각자 | HOST 만 **핫스팟 노트북** IP 로 |
