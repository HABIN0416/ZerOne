# Week 6 — 방(Room) 개념: 일단 엉성하게

"전체 채팅"에서 **방별 채팅**으로. 일부러 **전역 딕셔너리**로 시작해
상태가 흩어져 엉키는 고통을 느낍니다 (다음 주 객체화의 동기).

> 지난주의 깔끔한 `ChatServer`(부품 주입)를 **잠깐 내려놓고**, 방을 우선 '막' 붙여 봅니다.
> 곧(다음 주) 다시 객체로 정리할 거예요 — "엉성한 버전 → 좋은 버전"을 일부러 겪는 단계입니다.

## 파일
| 파일 | 설명 |
|------|------|
| `server.py` | 전역 `rooms` / `nicknames` / `where` + 명령 처리 (엉성) |
| `client.py` | 방 명령을 쓰는 클라이언트 |
| `messages.py`, `codec.py` | 이전 주차 재사용 |
| `make_ppt.py` / `Week06_방_엉성한버전.pptx` | 강의 슬라이드 |

## 실행 방법
```bash
python server.py            # 터미널 1
python client.py            # 터미널 2, 3, 4 …  (사람마다)
```
명령:
```
/create 잡담     방 만들기
/join 잡담       방 입장
/leave           방 나가기
/rooms           방 목록
/who             현재 방 멤버
```
그 외 입력 → 현재 방에만 전송. (방에 들어가야 대화 가능)

## 핵심 개념
- **라우팅**: 메시지를 어디로 보낼지 결정 → 이제 "그 방 멤버에게만"
- **전역 상태 3개**: `rooms`(방→소켓들), `nicknames`(소켓→이름), `where`(소켓→방)
- **엉성함의 정체**: 입장·퇴장마다 세 군데를 모두 맞춰야 한다 → 하나만 빠뜨리면 버그

## 왜 '고통'인가
```python
# /join 한 번에 세 군데를 손으로 맞춤
rooms[old].remove(conn)   # ①
rooms[arg].append(conn)   # ②
where[conn] = arg         # ③
# 퇴장 때도 같은 세 곳을 또 청소해야 한다
```

## 실습 / 과제
1. 전역 상태 버그 **일부러** 만나보기 — `rooms` 정리 한 줄을 주석 처리하고 방을 옮기면 "유령 회원" 발생
2. 빈 방 자동 삭제
3. (생각) 방 하나의 정보(이름·멤버·기록)를 한 곳에 모으면? → 다음 주 `Room` 객체
